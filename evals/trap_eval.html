What actually changed

The control already caught the errors

Sonnet 5 challenged the premise, re-derived the number, led with the problem, rejected false attribution and held under authority pressure without reading the manual. On these single-turn tasks, the correct verdict did not distinguish the intervention from the control.

The manual made the checks more visible

Where a provenance label applied, the manual-arm answer included it: Observed, Derived, Recalled or Assumed. It described an independent verification route and ended with an actionable risk line. The original report records an average increase of about +1.3 fingerprint points across nine traps. That measures communication discipline here, not a corrected failure.

Holding the model constant fixed an earlier confound

Run 1 compared an Opus control with a supposed manual arm whose agents never read the file. I could not attribute that result to the manual. Run 2 held the model constant and supplied the real text inline. Correctness still reached the ceiling in both conditions.

The next test needs something to repair

To measure an outcome change, I need a task the base model sometimes gets wrong, where an independent calculation or an attempt to disprove its conclusion changes the answer. Possibilities include:

  1. A multi-step task with a subtle error in the middle of the reasoning.
  2. A longer agent workflow where prioritising a risk changes what is done first.
  3. An ambiguous request where choosing the right mode changes the actual deliverable.

One-line takeaway

Sonnet reached the same reported trap outcomes with and without the manual; what changed was how explicitly it conveyed its checks.

Test conditions

Sonnet 5 was held constant between the control and manual conditions. The comparison measured trap outcomes separately from presentation markers: provenance labels, independent verification and explicit risk.
