Reading the result

The calibration gate is the whole test — and it failed.

The design pre-registered a gate: a task only counts if control fails it 25–75% of the time, so the manual has headroom to move the pass rate. Control failed 0% on all three tiers, including the hard Simpson's reversal (A wins both device segments; B's overall lead is a traffic-mix artifact) and the medium cost sheet (the worksheet used the event count, not events × 3 invocations — a 3× understatement). By the pre-registered rule, all three tasks are cut. Where the base model never fails, no intervention can be credited with success.

The sham arm did its job — and the style effect is mostly priming.

Run 2 couldn't separate "the manual's content" from "any careful-sounding preamble." Run 3's sham manual (sham_manual.md) is length- and structure-matched, same eight headings, filled with truisms — "be thorough, check your work, reconsider" — and zero specific procedures. On correctness, sham = manual = control = 100%. On style, the arms order manual > sham > control — but the sham closed most of the verbosity-and-care gap on its own. The markers unique to the real manual (provenance grades, a named disconfirming test, an explicit independent re-derivation route) appear only in the manual arm; the shared "careful-sounding prose" is priming the sham reproduces too.

This is the third run at the same wall.

Run 1 compared Opus control against a placebo manual arm (the agents never read the file) and couldn't attribute the result. Run 2 held the model constant and embedded the real manual — same ceiling. Run 3 added the sham control and a hard tier, and the ceiling held at every tier. Three converging runs: the ceiling is the model, not the manual.

To detect a capability effect, change the regime or the model.

Measuring whether the manual changes outcomes needs tasks where the base model sometimes fails — where re-derivation or self-attack actually flips the answer, not just its wording:

  1. Multi-step / long-horizon tasks with a subtle mid-chain error the model must catch by re-deriving.
  2. A weaker base model that fails these single-turn traps ~30–50% of the time, reusing the whole battery + sham design unchanged.

Honest confounds.

The manual and sham prompts are longer and both say "apply this to your answer," which itself primes length and care — so part of the manual-vs-control style gap is any preamble, and the sham arm exists precisely to expose that (it does). n=3 per cell is a screen, not proof, but 27/27 across three structurally different traps is not small-sample noise. And every task is single-turn, no tools — exactly the regime where a strong base model pattern-matches to correct, which is the wall all three runs hit.

One-line takeaway

Across three arms and three difficulty tiers, every Sonnet agent caught every trap. The manual's specific procedures appear only in the manual arm — but they label work that's already correct, not work they fixed. In the single-turn verify-an-artifact family at Sonnet tier, the manual is communication-discipline (and mostly priming), not capability. Detecting a capability effect needs a harder regime or a weaker model.
